# 기술 설명

## 디스크 구성

| 경로 | 내용 |
| --- | --- |
| `SLUS_211.93` | 실행파일(ELF). 파일 오프셋 = 가상주소 − `0xff000` |
| `FPACK/**.FPK` | 게임 데이터 묶음(88개). LZ 압축 항목 + 목록 헤더 |
| `SOUND/` | BGM·효과음·음성(`.XAG`). 음성은 영어 더빙 한 벌뿐 |
| `STR/*.PSS` | 로고·오프닝 동영상 |

`tools/fpk.py`가 FPK를 풀고 다시 묶습니다(LZ 압축기 포함). 바뀐 FPK가 원래 섹터에 들어가면 제자리에, 아니면 `DUMMY.DAT` 앞 빈 영역에 놓고 ISO9660 디렉터리 레코드와 UDF File Entry를 함께 고칩니다(`tools/isobuild.py`, `tools/udf.py`). 그래서 결과 ISO 크기가 원본과 같습니다.

## 문자열 (seq 스크립트)

화면 문자열은 FPK 안의 `.seq` 스크립트에 NUL로 끝나는 레코드로 들어 있고, 스크립트 코드가 절대 오프셋(u32)으로 참조합니다.

- 레코드는 16바이트(일부 4바이트) 정렬로 시작하고, 정렬 끝까지 0으로 채워진 구간이 그 레코드의 슬롯입니다(`tools/seqtext.py`).
- 번역이 슬롯에 들어가면 제자리에 쓰고, 넘치면 파일 끝에 붙인 뒤 u32 참조를 모두 새 위치로 바꿉니다(제자리 1,741곳, 이동 259곳).
- 4바이트 정렬의 8바이트 미만 레코드는 스크립트 키일 수 있어 건드리지 않습니다.
- 캐릭터 선택 화면의 "Time Limit"은 글자마다 따로 그리는 구조라, 4번째 글자 자리에 "제한 시간" 전체를 넣고 나머지 글자는 공백으로 바꿨습니다.
- 능력치 문구("Player's ATK increased by 1" 등)는 규칙으로 번역하고, 엔딩 크레딧은 직함·배역 표(`ROLE`, `CAST`)로 옮깁니다(`tools/build.py`).

## 한글 인코딩과 폰트

- 게임 폰트는 SJIS형 2바이트 문자를 별도 경로로 처리합니다. 한글은 리드 `0x81~`, 트레일 `0x40~0x7E·0x80~0xFC`(리드당 188자)로 배정하고, 글리프 번호 = 96 + 순번입니다.
- 폰트 TXD(원래 256×128, 16열)를 512×512 PSMT4(CT16 업로드), 32열 아틀라스로 다시 만들고, 원래 ASCII 128자를 새 배치로 옮긴 뒤 한글 534자를 그립니다.
- TXD 헤더의 크기·TEX0·업로드 길이를 새 크기로 고치고, 필드 `0x98`(팔레트 위치, 256바이트 블록 단위)을 `픽셀 크기 // 256`으로 맞춥니다. 이 값이 틀리면 글자 색이 깨집니다.

## 실행파일 패치

- 1바이트 글리프 경로(`0x14F020~`): UV 계산을 16열 → 32열, 셀 16px / 512로 바꿉니다.
- 2바이트 글리프 경로(`0x14EE98~0x14EF54`): 원래 일본어 처리를 지우고, 리드·트레일 바이트에서 한글 글리프 번호를 계산해 폭 15px·높이 16px로 그리는 코드로 바꿉니다.

## 그림 글자

`tools/imgtext.py`의 `IMG` 표가 "TXD/텍스처 이름 → 한글"을 정합니다(167항목, 텍스처 215장).

1. 원본 텍스처를 풀어(`tools/tex.py`, `tools/gs4.py`) 글자 영역을 찾습니다.
2. 원본 글자 본체의 세로 그라데이션과 외곽선 색을 뽑습니다.
3. 사진 위 글자(스테이지 이름 등)는 연결 요소별로 넓힌 마스크로 지운(inpaint) 뒤 다시 씁니다.
4. 한글을 같은 그라데이션·외곽선으로 그리고 원래 팔레트로 양자화해, 크기와 팔레트를 바꾸지 않고 다시 씁니다.

## 16:9 와이드 패치

PCSX2 내장 `SLUS-21193_E246AA30.pnach`(Little Giant)는 투영 행렬을 만드는 세 곳(`0x11FF98`, `0x121A90`, `0x1224A0`)의 가로 배율 상수를 `0x3FA51EB8` → `0x3FDC1ADE`로 바꿉니다. 한글패치는 이 주소를 건드리지 않으므로, 같은 내용을 한글판 CRC(`64836393`)로 옮겨 `patches/`에 둡니다. 실행파일을 바꾸는 새 버전마다 CRC를 다시 계산해 파일 이름을 맞춥니다.
